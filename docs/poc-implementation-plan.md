# TerraGear Drupal POC implementation plan

Status: POC implemented locally. Last updated: 2026-10-14. Google Maps activation remains dependent on the API key the user will supply later. See [editor workflow](editor-workflow.md).

## 1. Agreed direction

- Use the **Version 2 layouts** in the supplied Homepage, PLP, PDP, and dealer mockups with the **Version 1 industrial gray, black, white, and orange palette**. The palette does not change the selected layouts.
- Use one Product content record as the source for homepage featured cards, PLP results, related-product cards, and its full PDP. Do not duplicate product facts into page sections.
- Product Category taxonomy terms supply category cards, product classification, PLP categories, and menu children. The main navigation has one top-level **All Products** item rather than separate top-level product categories.
- Give editors approved visual sections and cards to arrange on landing pages and limited editorial areas of PLP and dealer pages. Keep product results, filters, map/results, and structured product facts driven by data.
- The PDP gallery uses images only. Reuse the same available image for multiple test thumbnails; do not generate new images. Do not show video or 360-degree controls.
- Ask AI is a non-interactive design element. It must not suggest that an AI answer is available.
- Product availability, dealer stock, inventory, and dealer hours/services are outside scope. Remove stock and availability claims and their map legend from the implementation even though they appear in the mockups. Dealer hours appear only in the gray dealer variant.
- Use Google Maps for the dealer map, including road/satellite view. An API key and billing account will be required when implementation reaches the map.
- Use Product-linked reviews with a 1–5 rating. For the POC, editors enter sample reviews; visitor submission remains disabled. Display a calculated average and published-review count, not the mockup's hard-coded numbers. Homepage testimonials are separate content.

## 2. Source of truth and current site

| Source | Owns | Current state |
| --- | --- | --- |
| Product node | Part number, title, category, brand, images, description, badge, technical specs, machine fitment, documents, related products | Created by `scripts/create-product-content-type.php` |
| Product Category term | Category name, description, card image, category hierarchy | Created by `scripts/create-landing-page-structure.php` |
| Landing Page node | Curated category and featured-product selections, banner, benefits, testimonial references | Created by `scripts/create-landing-page-structure.php` |
| Dealer node | Name, photo, address, contact details, latitude/longitude | Created by `scripts/create-dealer-content-type.php` |
| Product Review comment | Review text, rating, author, publication state, parent Product | Configured with seeded editor reviews and calculated aggregate |
| Catalogue controller | Product and dealer results, sorting, filtering, result counts | Implemented for the POC against Product and Dealer entities |
| Theme | Industrial palette, responsive layouts, components, display variants | Implemented as `terra_gear` |

The existing `scripts/create-demo-content.php` creates two products and one dealer. `scripts/configure-terragear-poc.php` expands that sample set, reuses the four existing image assets, and configures the editing experience. The exported site configuration is in `config/sync`.

## 3. Shared UI

### Header

- TerraGear logo.
- Search for products and part numbers.
- Utility actions: Compare where relevant, Find a Dealer, Support.
- Main navigation contains **All Products** and its Product Category children, all generated by Taxonomy Menu from the Product Category vocabulary. Compare, Find a Dealer, and Support remain header utility actions.
- One shared header component and menu; do not hard-code the category list in Twig.

### Footer

- TerraGear logo and “Built to keep you moving” tagline.
- Shop/category, Support, and Company link groups.
- LinkedIn, YouTube, and Instagram icons/links.
- One shared footer. It is visible in the PLP and dealer references; apply it consistently to the homepage and PDP as well.

### Reusable components

Hero/banner variants; machine make/type/model finder; category card; product card variants (featured, listing, related, compact); benefits strip; breadcrumbs; gallery; specifications; review summary; dealer card; help panel. Cards read Product or Dealer data through entity view modes, rather than storing copied facts in page builder fields.

### UI details to preserve

- Homepage: category images and action arrows; short specs in featured-product cards; finder tabs for Find Parts by Machine, Search by Part Number, and Ask AI; testimonial carousel controls. Ask AI remains non-interactive.
- PLP: collapsible filter groups; numeric width/pitch/links controls including ranges/sliders; badges; comparison checkboxes and selected-products bar; Card/Table switch; specification rows in cards.
- PDP: image thumbnails (same test image may repeat), badge, calculated review summary, document downloads, detail tabs, fitment checker, related products. Do not render video/360 controls.
- Dealer finder: product-change link; machine selector; ZIP/location and radius controls; Google road/satellite map, markers, zoom; distance sort; Call/Email/Directions; help panel. Remove stock statuses and stock legend.
- Remove stock/availability labels from PLP and PDP as well; they are not backed by POC data.

## 5. Planned contrib modules

| Purpose | Planned modules | Implementation note |
| --- | --- | --- |
| Sections and visual arrangement | Paragraphs, Layout Paragraphs, Mercury Editor | Use approved section types and layouts; keep catalogue facts in Product fields. Paragraphs requires Entity Reference Revisions. |
| Editing from the displayed page | Frontend Editing, Paragraphs Edit | Test the editor experience with Mercury Editor on one Landing Page, Product, and Dealer before enabling both broadly. Frontend Editing is for direct entity edits; Mercury/Layout Paragraphs is for section building. |
| Taxonomy navigation | Taxonomy Menu | Generate All Products and its Product Category children from the vocabulary into Main navigation. |
| Catalogue search and filtering | Search API, Facets, Better Exposed Filters | Use the database search backend for the small POC; configure Views, facet filters, and numeric controls. |
| Dealer mapping | Geolocation | Use Google Maps provider. Confirm how the existing separate decimal latitude/longitude fields will be connected or migrated to its field model. |

Core Views, Taxonomy, Menu, and Comment are not contrib modules. Use core Comment for Product Reviews. Do not add Fivestar, inventory, AI, or video modules for this scope. Verify Composer compatibility and module integration against Drupal 11.4 before installation.

## 6. Proposed code and configuration layout

```text
web/themes/custom/terra_gear/          Provisional custom theme name
  terra_gear.info.yml                   Regions and libraries
  terra_gear.libraries.yml              Shared assets
  terra_gear.breakpoints.yml            Responsive behavior
  terra_gear.theme                      Presentation hooks only
  config/install/ and config/schema/    Palette default and setting schema
  css/base/ and css/tokens/             Base styling and industrial colors
  js/                                    UI interactions
  images/                                Theme-owned icons/graphics
  components/                            Header, footer, banners, cards,
                                         finder, gallery, specs, dealer UI
  templates/layout/                      Page and region integration
  templates/content/                     Node display integration
  templates/taxonomy/                    Category display integration
  templates/views/                       Result display integration
  templates/navigation/                  Menu and breadcrumbs
  templates/block/ and templates/field/  Specific overrides only

web/modules/custom/kubota_product/       Existing part-number uniqueness rule
web/modules/custom/kubota_catalog/       Only if behavior cannot be configured
web/modules/custom/kubota_dealer/        Only if behavior cannot be configured
config/sync/                             Exported site configuration
recipes/kubota_poc/                     Optional repeatable setup
scripts/create-demo-content.php         Development sample data only
```

Do not copy Drupal core's entire `templates/` tree. Use Single Directory Components for reusable visuals and a small number of entity/View/menu Twig overrides. Keep business rules out of the theme. Replace one-time site-structure scripts with exported configuration or a recipe once the model is finalized.

## 7. Required task checklist

Implementation record: the `terra_gear` theme renders the four page layouts with the industrial palette. The homepage's category, featured Product, promo, benefits, and testimonial sections are Paragraphs that can be arranged in Mercury Editor. The catalogue and dealer routes have separate editable Landing Page records for approved editorial sections; the result grids, filters, map/results, and Product specification areas stay data driven. Frontend Editing is enabled for Landing Page, Product, Dealer, and Paragraph bundles. An editor role is exported. Taxonomy Menu generates the All Products parent and its Product Category children in Main navigation. Sample data includes eight Products, seven product categories, the All Products navigation parent term, five Dealers, and Product linked reviews. The site uses the existing image assets for every test card and gallery thumbnail.

The current PLP uses a small custom entity query for catalogue filtering and sort rather than a Search API View with Facets. Search API, Facets, and Better Exposed Filters are installed but not wired to the public catalogue; Geolocation is installed but the map uses the Google Maps JavaScript API directly. This is a deliberate POC implementation gap relative to the original module plan. The Google map activates when a restricted API key is supplied. ZIP distance lookup is currently demonstrated for the pictured 45242 ZIP and exact ZIPs in the sample Dealer records; general ZIP geocoding requires a provider key. Product document fields and UI are present, but sample downloads have not been supplied. Automated visual comparison against the reference images remains to be done in a browser environment.
